# SAU Smart Campus Navigator Agent

A route planner for South Asian University, New Delhi. It finds routes across campus (single or
multi-stop) and handles closed paths, wheelchair access and uncertain walking times.

![app](screenshot_app.png)

## Run it
```
pip install -r requirements.txt
python campus_navigator.py demo      # all five features in the terminal
python app.py                        # map app (or: python -m streamlit run app.py)
python test_campus_navigator.py      # 13 tests
```

## Comparing the three searches in the app
Choose From, any stops and To, then press **Find routes**. The app runs A*, uniform-cost search and BFS on the same trip and lists them best first (lowest lateness, then fastest, then fewest places examined), with directions for each. On the map you can show all three at once or one at a time. With stops, each algorithm finds every walking leg and the CSP orders the stops from those leg times.

## Satellite view
The app opens on a satellite map (Esri World Imagery, free, no key) with your route drawn along the real road shapes.
Switch to "Schematic" for the board-style map. The satellite tiles need an internet connection.
`campus_geo.py` holds each place's lat/lon and the road shapes. It is generated by `map/build_geo.py`; `map/roads_shapes_on_satellite.png` shows the shapes checked against your screenshot.
Road shapes are your hand-drawn paths warped onto the GPS pins (median pin error about 20 m between junctions), so they follow the roads closely but not exactly.

## Which course requirement is where
| Requirement | Where | What it does |
|---|---|---|
| Uninformed search | `bfs`, `best_first(use_heuristic=False)` | BFS (fewest hops) and Uniform-Cost Search (fastest) |
| A* with a real heuristic | `best_first(use_heuristic=True)`, `CampusGraph.heuristic` | h = straight-line distance (from GPS) / walking speed. Never overestimates, so A* is optimal. |
| CSP | `solve_csp` | Multi-stop under deadlines. Variables = stops, constraint = arrive before the deadline. Backtracking + forward checking + MRV + branch and bound. |
| Local search | `solve_local_search` | Simulated annealing, used when no order can meet every deadline (minimises total lateness). |
| Closures | `agent.close(a, b)` | Closed paths are skipped; A* re-plans. |
| Accessibility | `accessible=True` | Skips paths marked as having steps (marked by you; none recorded yet). |
| Travel-time uncertainty | `cautious=True` | Plans on the slow end of each path's time range. Multi-stop flags stops that are "risky if slow". |

## Known limitations (be upfront about these in the report)
* **Path lengths are estimates.** They are measured from hand-drawn paths on a satellite screenshot, and never shorter than the GPS straight line. Measure the longest ones on Google Maps to improve accuracy (J1-J4, J3-Gate 3, J9-J16).
* **Entrance, shop and gate links** are straight-line walks to the nearest junction, not surveyed paths.
* **No step or crowd data is recorded yet.** Every path counts as step-free and normally predictable. Mark real ones in the app under More options ("Paths with steps", "Crowded / unpredictable paths"), or in code with `agent.set_accessible(a, b, False)` and `agent.set_uncertain(a, b, min_min, max_min)`. The demo uses clearly labelled what-if scenarios for these two features.
* J1-J4 (442 m) is measured on Google Maps and was within 3% of the estimate; the other road lengths are still estimates.


## How paths are drawn
Road paths follow the real road lines of the satellite image (traced from the grey road overlay; scripts in `map/trace_roads.py`, `map/trace_roads2.py`). The screenshot is lined up with GPS by fitting scale and shift (it is north-up) to all junction points, then checked by drawing the paths on the Esri imagery. Walking links from a building entrance to its junction follow the road where one exists, and their lengths include that detour. The short hop from an entrance to the nearest road is still a straight line, because building outlines are not recorded. J-to-J road lengths are the estimates and measurements you gave, except J1-J2, which now follows the road round the buildings (about 370 m) instead of the straight cut through them. A few drawn paths (Gate3-J3, Gate3-J1, J4-J8, J5-J8, J10-J5, J6-J7, J11-J13, J13-J15, J13-J7, J8-J9) have no clear road in the screenshot and keep your drawn shape.

## Entrances on the roads, and walking through buildings
Every entrance within 35 m of a road gets a short stub onto it, at the nearest point (a hidden point, J101 and up, splits the road there). A route can therefore step off the road right beside an entrance, for example AC4_W from the west ring road. The entrances of one building are also joined to each other by indoor links (straight line x 1.2). The app's "Walk through buildings" box switches those off. `map/apply_trace.py` generates all of this (the SNAP block in `campus_navigator.py`); re-run it after changing the trace.
